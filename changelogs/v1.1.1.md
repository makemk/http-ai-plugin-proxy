# v1.1.1 性能优化

## 改动
- **路由匹配预编译**：`src/network/domain-matcher.js` 新增 `buildRoutingMatcher()`，启动时把 AI 域名、国内直连后缀、自定义规则编译成正则，替代原来每次请求的多重 `endsWith` 循环。`src/core/server.js` 热路径（`isDirectBypass` / `isAiDomain`）改用预编译匹配器，实测路由判断提速约 4 倍。
- **消除每请求重复计算**：`Proxy-Authorization` 头改为按配置缓存（配置热重载时自动失效），原来每个请求都做一次 base64；`getTlsOptions()` 原来每次建连都调 `fs.existsSync`（有 CA 时还同步读文件），现在只构建一次并缓存，TLS 会话票据仍每次单独附加，不影响会话复用。
- **默认 TLS 1.3**：`tlsMinVersion` 默认值从 `TLSv1.2` 改为 `TLSv1.3`，冷连接握手从 2-RTT 降到 1-RTT（中美链路约省 150~200ms/次）。设置里仍可改回 1.2。

## 刻意保留的高性能调优（未动）
- 预热池 25 秒空闲轮转、256KB 流缓冲对齐、30 秒延迟探测——均为面向多核旗舰 CPU 的极限低延迟设计，保持原样。

## 说明
- 保持 JS（VS Code 扩展宿主就是 Node，瓶颈在网络 RTT 而非本地 CPU，重写语言收益为零）。
- 所有改动保持原有行为与配置兼容；`buildRoutingMatcher` 与旧循环逻辑做了等价性校验。
