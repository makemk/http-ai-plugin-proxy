# v1.2.0 HTTP/2 多路复用上游隧道

## 背景
网关（gost `browser-gateway-h2`）本来就支持 HTTP/2，但插件一直用 HTTP/1.1 CONNECT，
每个请求都要一次 CONNECT 往返（中美链路约 150~200ms），突发时还会撞上预热池
6~16 个 socket 的上限、触发冷 TLS 握手。本版本把插件侧补齐到 H2。

## 改动
- **新增 `src/core/h2-pool.js`（H2SessionPool）**：维护 2 个常驻 H2 会话（ALPN h2），
  每个代理请求只开一个 extended-CONNECT stream（`:method: CONNECT` +
  `:authority: host:port` + `proxy-authorization`），多路复用在同一条 TLS 连接上。
  - CONNECT HEADERS 与请求头（plain HTTP）/`head`（CONNECT 法）一起乐观发出，
    不等待 200， effectively 0-RTT。
  - 会话级 PING 保活（15s）、10 分钟优雅轮转、GOAWAY/error/close 处理、
    熔断器（连续 5 次失败冷却 60s）。
  - per-stream 流控窗口 256KB，与现有转发缓冲对齐。
- **`src/core/server.js`**：`handleConnectRequest` 与 `handleHttpRequest` 的上游
  路径优先走 H2，任何失败自动回退到原有 HTTP/1.1 路径（warm pool + failover 保持不动）。
- **新增配置 `httpAiProxy.enableH2Multiplex`**（默认 true），可一键切回纯 H1。
- **本地 `keepAliveTimeout` 5s → 30s**：客户端长连接复用，减少本地握手。
- 健康检查新增 `h2Multiplex` 段：会话数、stream 数、熔断状态、隧道统计。
- `tunnel-bridge.js` 的 socket 调优加特性检测，兼容 H2 stream（Duplex）。

## 兼容性
- VPS 侧零改动（已实测 gost 接受 H2 CONNECT 并返回 200，隧道双向可用）。
- H2 失败（网关不支持/ALPN 未协商出 h2）时全自动回退 H1，无感。
- 直连旁路、warm pool、failover、配置热重载行为不变。

## 实测
- 20 并发 H2 隧道：全部 200，隧道内 TLSv1.3 + HTTP 端到端可用。
- 完整代理链路：`curl -x` 经插件访问 https/http，成功。
